# 双模式开发与部署指南

Neon Crate 支持两种运行模式，可以在同一套代码中无缝切换。

## 模式对比

| 特性 | 本地开发模式 | AIO 生产模式 |
|------|-----------|----------|
| **前端框架** | `output: 'standalone'` | `output: 'export'` |
| **前端端口** | 3000/3001 | 8000 |
| **后端端口** | 8000 | 8000 |
| **API 代理** | ✅ 启用（Next.js 代理） | ❌ 禁用（同域） |
| **构建命令** | `npm run dev` | `npm run build` |
| **Docker** | ❌ 不需要 | ✅ 需要 |
| **前端资源** | 内存中 | 静态文件（`/static`) |

---

## 🚀 本地开发模式

### 快速开始

**终端 1 - 启动后端：**

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 -m uvicorn app.main:app --reload
```

后端运行在 `http://127.0.0.1:8000`

**终端 2 - 启动前端：**

```bash
cd frontend
npm install
npm run dev
```

前端运行在 `http://localhost:3000`（或 3001 如果 3000 被占用）

### 工作流程

```
浏览器 (localhost:3000)
    ↓
前端 Next.js (standalone 模式)
    ↓
代理到 /api/v1/*
    ↓
后端 FastAPI (127.0.0.1:8000)
    ↓
数据库 SQLite (data/app.db)
```

### 环境变量

`.env.development.local`:
```bash
NEXT_PUBLIC_BUILD_MODE=dev
NEXT_PUBLIC_API_BACKEND=http://127.0.0.1:8000
```

### 特点

- ✅ 前后端分离，独立开发
- ✅ Next.js 自动代理 API 请求
- ✅ 支持热更新（HMR）
- ✅ 易于调试和测试

## 🐳 AIO 生产模式（Unraid Docker）

### 快速开始

**本地构建并推送：**

```bash
cd /path/to/Neon-Crate

# 前端自动构建为 output: 'export' 模式
docker build -t x1000qaq/neon-crate:v1.0.0 .

# 推送到 Docker Hub
docker push x1000qaq/neon-crate:v1.0.0
```

**Unraid 中部署：**

```yaml
version: '3.8'
services:
  neon-crate:
    image: x1000qaq/neon-crate:v1.0.0
    container_name: neon-crate
    restart: unless-stopped
    ports:
      - "8000:8000"
    volumes:
      - ./data:/app/data
      - /your/downloads:/storage/ready_for_ai
      - /your/media:/storage/media
    environment:
      - JWT_SECRET_KEY=your-strong-key
      - TMDB_API_KEY=your-api-key
```

启动：
```bash
docker-compose up -d
```

访问：`http://Unraid-IP:8000`

### 工作流程

```
浏览器 (Unraid-IP:8000)
    ↓
FastAPI (单端口 8000)
    ├─ 静态文件服务 (/)
    └─ API 路由 (/api/v1/*)
         ↓
    数据库 SQLite (/app/data/app.db)
```

### 构建过程

Dockerfile 多阶段构建：

1. **阶段 1 - 前端构建**
   - 环境变量 `NEXT_PUBLIC_BUILD_MODE=aio`
   - `npm run build` 生成静态导出
   - 产物：`frontend/out/`

2. **阶段 2 - 后端打包**
   - 复制后端代码
   - 复制前端产物到 `backend/static/`
   - 启动 Uvicorn 在 8000

### 特点

- ✅ 单容器、单端口
- ✅ 零跨域配置
- ✅ NAS 友好（支持挂载点）
- ✅ 生产级稳定性（WAL + 原子写入）

## 🔄 从开发到生产

### 工作流程

```
本地开发
  ↓
npm run build（本地测试静态构建）
  ↓
git push origin master
  ↓
docker build -t x1000qaq/neon-crate:v1.0.0 .
  ↓
docker push x1000qaq/neon-crate:v1.0.0
  ↓
Unraid: docker-compose up -d
  ↓
生产环境
```

### 关键文件

| 文件 | 用途 |
|------|------|
| `frontend/next.config.js` | 根据 `NEXT_PUBLIC_BUILD_MODE` 切换模式 |
| `frontend/.env.development.local` | 本地开发环境变量 |
| `Dockerfile` | 多阶段构建，设置 `NEXT_PUBLIC_BUILD_MODE=aio` |
| `backend/app/core/app_factory.py` | SPA 回退处理（两种模式都支持） |

## 🛠️ 常见操作

### 本地测试生产构建

有时你想在本地测试生产的静态导出模式：

```bash
cd frontend

# 构建静态产物
NEXT_PUBLIC_BUILD_MODE=aio npm run build

# 启动静态服务器（需要另外安装）
npx http-server out -p 3000
```

### 只推送后端代码

如果只改了后端逻辑，可以只重新构建后端层（Docker 缓存会使用之前的前端层）：

```bash
docker build --no-cache -t x1000qaq/neon-crate:v1.0.0 .
```

### 本地调试 Docker 镜像

```bash
# 本地构建
docker build -t neon-crate-local .

# 本地运行
docker run -p 8000:8000 -e JWT_SECRET_KEY=test neon-crate-local
```

## 📋 环境变量总结

### 前端

| 变量 | 用途 | 开发值 | 生产值 |

| 变量 | 用途 | 默认值 |
|------|------|-------|
| `JWT_SECRET_KEY` | JWT 签名密钥 | `（必须设置）` |

| `DOCKER_STORAGE_PATH` | 存储挂载点 | `/storage` |

## 常见问题

### Q: 为什么本地开发时前端刷新报 404？

**A:** 本地开发时，Next.js 的 rewrites 只在服务器端工作。刷新页面时浏览器直接请求前端，而不是通过代理。这是正常的，不影响开发体验。在生产 AIO 模式下，SPA 回退处理会正确处理所有路由。

### Q: 本地开发改了后端代码，前端为什么没更新？

**A:** 前端只会代理 API 请求，不会重新加载后端代码。后端用 `--reload` 启动时会自动重新加载。刷新前端页面（F5）重新请求 API 即可看到更新。

### Q: 如何在 Unraid 中更新到最新版本？

**A:** 
```bash
# 在 Unraid 中
docker pull x1000qaq/neon-crate:latest
docker-compose up -d  # 自动拉取新镜像并重启
```

### Q: 生产环境可以启用 DEBUG 模式吗？

**A:** 可以，但不推荐。在 `docker-compose.yml` 中添加环境变量：
```yaml
environment:
  - DEBUG=true
```

然后查看日志：`docker logs -f neon-crate`
